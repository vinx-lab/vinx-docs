# 通用多项目文档中心架构

更新日期：2026-09-26；状态：核心导入与展示链路、自动同步、管理后台、跨项目搜索、增量刷新、页面短链接、编辑与批注均已实现；运行形态为单个 Go 程序。

## 选择的方案

一个 Go 程序（前端资源内嵌）在 8000 端口同时提供生成的站点、管理接口、页面短链接和批注接口，每个登记项目拥有自己的 Docsify 入口。Docsify 是浏览器端的文档渲染器，不要求每个项目部署一个服务器进程。进程内有一个文件变化监听协程实现自动同步；批注存在家目录的 SQLite 里（纯 Go 驱动，不需要 C 编译器）。没有 Nginx 或 Docker，Linux、macOS、Windows 用同一套代码（后两者尚未实测）。部署细节见 [部署与验证](deployment.md)。

```text
浏览器 localhost:8000
  ├─ /                           项目文档（卡片内含各自最近更新与待处理批注）、页面、跨项目搜索、访问二维码
  ├─ /admin.html                 管理后台：接入、改名、排除规则、自动同步设置
  ├─ /search-index.json          跨项目搜索索引（构建时产出）
  ├─ /projects/project-a/        项目A阅读入口（含 #/__scope.md 范围说明页）
  ├─ /projects/project-a/sheet.html  工作簿只读预览
  ├─ /projects/project-b/        项目B阅读入口
  ├─ /published.html             页面：左侧按发布时间倒序，右侧直接显示，默认跟随最新
  └─ /a/<短码>/                   agent发布的单个页面（控制服务实时读取源文件）
          │
          └─ 共享固定版本的本地资源：docsify / mermaid / SheetJS / qrcode
```

项目A/B是说明性示例，不是已注册项目。服务默认监听 `0.0.0.0:8000`，本机可用localhost，其他设备使用主机IP；跨设备可达性必须实际核验。

## 数据流与权威来源

```text
各项目原始docs目录（项目自身维护，一个项目可以有多个目录）
  -> 显式注册配置（每个目录带项目内前缀，整体收录 + exclude 黑名单）
  -> 路径/文件名/类型/内容四层强制审查
  -> 增量生成只读副本、导航、范围说明页与搜索索引
  -> 同一进程按路径给出 MIME、CSP、附件与 404
  -> 每个项目自己的Docsify页面

inotify 监听注册根 --防抖--> 触发同一条构建链路（与手动同步共用一把操作锁）
```

原始文档始终是权威来源；注册表只记录如何读取它，导出目录只是可重建的展示缓存。agent在项目里写文档，人通过阅读器查看同一批内容的展示副本，不新增文档数据库，不让阅读器自动编辑业务项目。

配置、代码、前端资源和测试归 Vinx Docs 维护；外部项目只需提供明确的文档路径和排除规则，不需要复制Docsify模板或安装运行依赖。

## 两个入口方向

同一台文档服务器，内容进来有两个方向，看的都是本机的原始文件：

- **项目注册**：人或页面主动登记一个文档目录，整目录收录、inotify自动同步，生成可重建的阅读副本（上面的数据流）。
- **短链接发布**：agent做完一个页面，用 `vinx-docs publish <入口.html>` 登记入口页和文件清单，得到 `/a/<短码>/`。不复制、不生成副本，控制服务按请求实时读取源文件；改源文件后已打开的页面自动刷新。封装为 `vinx-docs` skill。

短链接的设计参照 claude.ai Artifact 的「入口页 + 显式文件清单」，差别是不复制内容：

```text
publish <入口.html> [--file ...] [--root 目录]
  -> 从入口页沿 HTML/CSS/JS 相对引用收集文件清单（只放行清单，不放行目录）
  -> 逐个做路径、符号链接、隐藏/凭据文件、私钥内容检查
  -> 写入 config/artifacts.json（同一入口页重复发布沿用原短码）

GET /a/<短码>/<路径>  -->  服务
  -> 路径必须在清单里；每次请求重新做同样的检查
  -> 读取源文件返回；HTML末尾插入 /assets/artifact-live.js（带当时版本号）
  -> 页面每2秒查 /a/<短码>/__docsify_x/version（清单文件的mtime/大小摘要），变了就reload
```

安全边界：短链接页面与管理后台同属8000的origin，因此响应带 `Content-Security-Policy: sandbox allow-scripts …`（不给 `allow-same-origin`）。页面的origin变成 `null`，写接口的 `Origin` 校验会拒绝它；加载资源只允许本站，外部CDN被拦截。只对 `Origin: null` 回 `Access-Control-Allow-Origin: null`，页面才能 `fetch` 同清单里的JSON。短链接响应只能有这一条策略：如果再叠加站点级 CSP，两条策略取交集，会拦掉页面脚本和 iframe（由 `internal/server/server_test.go` 守住）。

源文件删除或移走后，对应链接404，不保留历史版本；登记表只由 `publish`/`unpublish` 修改，与项目的构建刷新互不影响。

## 编辑与批注

```text
浏览器（阅读页 / 页面）
  ├─ 编辑：GET /api/file?target=… → CodeMirror → POST /api/file/save {target, content, baseVersion}
  │        控制服务：解析目标 → 安全检查 → 版本对比（不一致回 409） → 留历史 → 原子写 → doc 目标做增量刷新
  └─ 批注：选中文字 / 点选元素 / 拖框 → POST /api/comments → 「交给agent」→ POST /api/comment/update {action: send}
                                                        │
             ~/.local/share/vinx-docs/vinx.db（comments / replies / subscriptions）
                                                        │
  Claude Code 会话：Monitor 挂 vinx-docs watch ──── 取走范围内已交给agent的批注，每条输出一行唤醒会话
  Codex 会话：vinx-docs subscribe ─────────────── 控制服务执行 codex queue 推送（未实测）
  任意 agent：vinx-docs comments / comment / claim / reply / resolve
```

目标写法：`doc:<项目ID>/<收录路径>`（必须在 manifest 里）、`a:<短码>/<清单路径>`（必须在短链接清单里）。只有 UTF-8 文本、不超过 2 MB 的文件可以编辑；保留 BOM 和 CRLF 换行；每个文件保留最近 20 份历史，放在家目录的 `.runtime/history/`。发布页的批注交互由注入的 `artifact-live.js` 在沙箱内完成，通过 `postMessage` 和外层通信，外层只接受 `event.source` 是这个 iframe 的消息。

链接地址：给人看的链接用 `server.publicBase`；没有配置时取本机的 Tailscale MagicDNS 名（人常在别的设备上打开），都没有才用 localhost。

## 多项目边界

共享服务进程、公共静态资源和维护程序；每个项目独立定义：

- 稳定ID、显示名称、一个或多个原文目录（各带项目内前缀）与首页。
- 导航树、正文相对链接、标题锚点。
- 项目内搜索路径与缓存命名空间；跨项目搜索走站点级 `search-index.json`，可在结果里区分来源项目。
- 排除规则、附件预览/下载映射，以及本项目的 `#/__scope.md` 范围说明页。

不能把整个机器的项目混在同一个侧栏。跨项目搜索是显式入口而不是默认侧栏合并：索引只包含已注册项目中已发布的Markdown与文本预览，每条结果标注所属项目，不改变任何项目的导航范围。

**不同URL路径不构成安全隔离。**同一个端口下的多个项目属于同一浏览器origin，当前没有身份认证或按项目授权。监听0.0.0.0后，能访问该服务的设备可能读取全部已发布资料；必须明确采用共同的信任边界并审查发布清单。若未来不同人员或客户需要权限隔离，应单独设计鉴权、origin/服务隔离，不以路径前缀代替授权。

## 文件展示策略

| 类型 | 第一版设计 | 限制 |
| --- | --- | --- |
| Markdown | Docsify正文、目录、章节导航与搜索 | 禁止执行文档脚本；不自动嵌入未允许文件 |
| HTML | 注册目录里的HTML：隔离预览，禁止脚本；需要脚本的页面走短链接发布（沙箱内允许脚本） | 注册目录的预览不执行脚本；短链接只能加载清单内的本站资源 |
| JSON、YAML、XML、配置、脚本等文本 | 转义后的只读代码预览，允许时下载原件 | 不执行；不能把示例中的命令自动交给shell |
| Mermaid代码块 | 用本地固定版本mermaid渲染为SVG，按需懒加载 | 渲染失败时显示错误而不是静默留空；不加载外部主题或字体 |
| CSV | 原件下载，可提供文本预览；优先链接已有Markdown矩阵 | 不承诺电子表格编辑 |
| XLSX | 独立预览页用本地SheetJS解析为只读表格，按工作表切换，并保留原件下载 | 只读，不提供编辑或回写；解析失败时退回下载 |
| 图片及其他格式 | 在明确允许后按安全MIME处理 | 未知格式不以HTML执行；SVG等主动内容单独审查 |

## 链接处理

根据源文件所在目录解析相对链接，而不是根据浏览器地址猜测。解析后必须确认目标在该项目允许清单中，再转换为Markdown阅读、HTML预览或附件地址。

中文路径、空格、URL编码和标题锚点需要保留并测试。不能重复编码，也不能为了让某个链接可访问就开放它指向的整个父目录。

指向仓库源码、其他项目或根目录规范的链接：默认显示本地路径与未纳入范围说明。确需展示根AGENTS/CLAUDE等文件时，后续增加显式单文件授权设计；不能用 `basePath: ../` 无限向上读取。

## 最小实现组件

代码在 `internal/` 下：`build`（登记、校验、构建）、`config`（家目录与配置路径）、`server`（服务与进程管理）、`watch`（自动同步）、`pages`（短链接）、`files`（编辑）、`comments`（批注）、`api`、`cli`；入口是 `cmd/vinx-docs`，前端资源在 `assets/` 并内嵌进程序。职责划分：

1. 注册配置与校验器：验证项目路径和命名，输出有效项目列表。
2. 导出/索引程序：筛选文件、构建副本、导航、类型映射与搜索清单。
3. Docsify壳与本地资源：根据项目ID加载自己的首页、侧栏及搜索范围。
4. 服务进程：提供导出站点并按路径处理 MIME、CSP、附件及 404，转发 `/api/` 与 `/a/` 到对应处理逻辑。
5. 管理入口：`/admin.html` 后台加 `/api/` 接口，覆盖接入、改名、排除规则、取消接入、自动同步设置、运行状态与构建报告；所有行为局限于 Vinx Docs 自己的家目录。
6. 变化监听：Linux 上直接通过系统调用使用 inotify，跳过隐藏与缓存目录，防抖合并连续保存；watch 超预算或平台没有 inotify 时降级轮询。
7. 构建缓存：按 mtime/大小判断复用，复用前确认输出副本仍在，避免被删掉的副本永远补不回来。
8. 测试：路径和生成器单测、控制接口契约、监听与防抖行为、HTTP安全边界、真实浏览器、多项目相对链接与业务不受影响检查。

## 不包含的能力

多人协作与实时协同编辑、页面数据存储、git 版本管理、写操作的账号权限；业务项目运行管理、agent调度/聊天、云同步、协同编辑、账号权限平台、在线Excel编辑，以及自动扫描整台开发机。自动同步只监听已注册的文档根，不监听整台机器，也不把文档刷新绑定到业务构建。
