# 0005 外部访问要登录，按转发头和域名识别，内网不变

状态：已采纳

## 背景

服务按单人、可信网络设计，没有账号。要经 HTTPS 反向代理用域名从外网访问时，不能把阅读、保存、登记和设置接口直接暴露出去；同时内网直连的使用方式（本机 agent、局域网、手机）不能因此变麻烦。

## 决定

- 只有一个访问密码，没有用户名和权限分级。
- 同一个端口服务内外两种访问。请求带任一转发头（`X-Forwarded-For`、`X-Forwarded-Host`、`X-Forwarded-Proto`、`Forwarded`、`X-Real-IP`），或 `Host` 是登记的外部域名，就按外部访问处理；不按来源 IP 判断，因为反代通常经内网或 tailnet 连进来。
- 外部访问未登录时只读放行：标为公开的项目、发布后一段时间内（默认 24 小时）的短链接，以及不含数据的页面外壳和静态资源。其余页面跳转登录，接口返回 401。
- 密码和外部访问设置只能在内网修改。

## 影响

- 内网行为和接口完全不变。
- 识别依赖反代配置：反代既改写 `Host` 又不加任何转发头时，外部请求会被当成内网。所以部署说明要求反代转发 `X-Forwarded-For` 和 `X-Forwarded-Proto`，并在后台登记外部域名作为第二道识别。
- 内网仍然没有权限控制；能直连端口的设备照旧可以做全部操作。
- 不取代 spec 0004 的快照分享：给不该连回本机的人，仍用快照。
