# 0006 发布到外部服务：适配器协议；命令只能在本机登记；内网或登录后才能发布和管理

状态：已采纳

## 背景

要把源文件发布到 Google Drive 等外部服务，以后还会接入更多服务商。各家的接口和授权方式差别很大，全部写死在主程序里会越来越重，也很难让别人贡献。

同时，8000 端口在内网没有鉴权（README「安全模型」），同一网络里的任何设备都能调用写接口，伪造 `Origin` 也不难。发布是第一个把数据发出本机、而且不可逆的写操作。

## 决定

- **主程序只定义协议**：每次调用启动一个进程，stdin 传一行请求，stdout 输出 NDJSON 事件（spec 0008）。官方适配器用 Go 写、编进主程序，以 `vinx-docs share-adapter run <id>` 运行，和外部适配器走同一套协议。不新增第三方 Go 依赖。
- **任意命令只能在本机命令行登记**：外部适配器（命令、清单路径、`passEnv`）只能用 `vinx-docs share-target` 登记。页面和接口只能管理内置适配器的服务商设置、账号和目标，提交命令相关字段一律拒绝。
- **内网或登录后才能发布、撤回和管理**：经反向代理的外部访问登录后（ADR 0005）和内网权限相同；未登录的外部访问（包括短链接免登录期内的访问者）只能看到公开内容，看不到发布目标，写接口返回 401。写接口要求 `Origin` 同源，沙箱里的短链接页面不能借登录状态发布。访问密码和外部访问设置仍然只能在内网修改。
- **能发什么、是否公开，在保存目标时决定**：目标默认不能发布任何来源，必须显式勾选；选择公开链接时要再确认一次。适配器返回的结果和目标设置不一致时，按失败处理。
- **凭据只在本机**：服务商密钥和目标密钥存在 0600 的配置文件里，只通过 stdin 传给适配器，页面上只显示「已设置」；OAuth 令牌由适配器写在每个账号 0700 的状态目录里。
- **执行方式**：主程序直接执行参数数组，不经过 shell；不继承主程序的环境变量；适配器只拿到临时副本。

## 影响

- 接入新服务商不用改主程序的发布流程：官方适配器按 spec 0008 的贡献规范实现，并通过离线一致性测试；用户也可以写自己的外部适配器，在本机登记。
- 内网设备和登录后的外部访问者可以在后台连接账号、新增目标，并把允许的页面发出去，但执行不了任何其他命令。这与现状一致：内网没有权限控制，登录后的外部访问者本来就能读到全部内容；外部一侧的安全性取决于访问密码。新增的风险是，内容可能被发到公开链接或别人的账号上，靠「公开要二次确认」和后台明确显示每个目标的账号来降低。
- 以后如果要在页面上登记外部适配器，必须先推翻这条记录：要么先给内网加上鉴权，要么证明页面没法借此执行任意命令。
- 外部适配器以 Vinx Docs 进程的身份运行，权限和主程序相同。安装第三方适配器，等于在本机运行第三方程序。
