# 架构决策记录

每个文件记录一个长期有效的重要决定：当时的背景、定了什么、带来什么影响。以后有人问「为什么这样设计」，看这里就能找到答案，不用翻聊天记录或 issue。

和 [需求说明](../specs/README.md) 的区别：需求说明讲一次改动怎么做，做完就结束；这里讲一个决定为什么这样定，长期有效。

业界通常把这类文档叫 ADR（Architecture Decision Record）。

## 规则

- 文件名 `NNNN-简短标题.md`，编号四位、递增。
- 已采纳的记录不改写结论。决定被推翻时，写一条新记录，并把旧记录的状态改成「已被 NNNN 取代」。
- 这些文件会公开，不写本机路径、主机名、个人或客户信息。

## 模板

```markdown
# NNNN 标题

状态：提议 / 已采纳 / 已被 NNNN 取代

## 背景
遇到了什么问题，有哪些约束。

## 决定
定了什么。

## 影响
带来的好处、代价和后续要注意的事。
```
