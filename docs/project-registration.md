# 项目注册路径约定

更新日期：2026-09-16；状态：一个项目可挂多个文档目录；收录范围为黑名单（每个目录整体收录 + exclude），include白名单已移除；自动同步、管理后台与内容级隐私规则已实现。

## 注册的含义

注册是允许 Vinx Docs 读取一个明确的项目文档根目录，并为它建立独立的阅读入口。注册不迁移文件、不把项目复制到本工具、不赋予访问整个仓库或整台机器的权限。

配置示例见 [projects.example.json](../examples/projects.example.json)。实际配置位于家目录的 `config/projects.json`（见 [部署与验证](deployment.md#家目录)），由服务启动和 `refresh` 读取；缺少配置时不导入任何项目。

## 配置字段

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| schemaVersion | 整数 | 示例为1；未来读取器应拒绝未知版本，不能静默误解析 |
| server.host | 字符串 | 负责人已指定0.0.0.0，监听全部IPv4网卡；跨设备可达性另行验证 |
| server.port | 整数 | 默认8000，必须可用且不在protectedPorts中 |
| protectedPorts | 整数数组 | 不允许服务占用的端口，用来避开本机其他服务；默认为空 |
| projects | 数组 | 显式注册的项目项，不自动扫描目录生成 |
| projects[].id | 字符串 | 唯一URL标识；建议小写字母、数字、连字符，不能含路径分隔符或`.`/`..` |
| projects[].name | 字符串 | 浏览器显示名，可为中文 |
| projects[].docsPath | 字符串 | 单目录项目的写法：主机上的明确文档目录绝对路径。与 `roots` 互斥 |
| projects[].roots | 对象数组 | 多目录项目的写法：`[{prefix, path}]`。`path` 是主机上的绝对目录，`prefix` 是它在项目里的位置；`prefix` 留空表示直接挂在项目根下 |
| projects[].home | 字符串 | 项目内路径（含前缀）的Markdown首页，必须落在某个已登记目录内 |
| projects[].exclude | 字符串数组 | 相对文档根的排除模式，匹配整段相对路径：支持`*`通配（可跨目录，`*.py`命中任意层级）、以`/`结尾的目录、`目录/**`，以及表示零层或多层目录的`**/`（`**/*.json`同样命中顶层文件）。只写`.py`不会命中任何文件。命中目录时整棵子树被剪枝，不进入遍历；不能关闭强制的隐藏/凭据/路径安全限制 |
| settings.autoSync | 布尔 | 是否监听注册根并自动重建；关闭后只能手动同步 |
| settings.debounceSeconds | 整数 | 文件停止变化多少秒后才重建，用于合并连续保存 |
| settings.recentDays / recentLimit | 整数 | 首页各项目卡片“最近更新”的时间范围与每个项目最多条数（卡片默认显示前3条，可展开） |

`schemaVersion` 为1的旧配置在读取时自动迁移：丢弃 `include`，范围变成整个注册根，`exclude` 原样保留。显式写成 `schemaVersion: 2` 却仍带 `include` 会直接报错，不会被静默忽略。

这是设计接口，不是已经发布的兼容标准。首次实现后需要将校验规则、错误结果和迁移行为固化为测试；改变字段时同步修改文档和示例。

## 配置示例

可以将任意明确的本机文档根目录写入家目录的 `config/projects.json`。例如：

- ID：`project-a`
- 文档根：`~/projects/project-a/docs`
- 首页：`README.md`
- 预期阅读路径：`/projects/project-a/`

这只是路径形状示例，不代表该目录已被读取、注册或部署。

## 必须校验的边界

1. 配置端口为整数、在允许范围内、未受保护且当前可用；不能更改其他服务以让出端口。
2. 项目ID唯一且可用于单路径段，显示名作为文本渲染，不能作为HTML代码。
3. docsPath为本地明确目录，不接受HTTP地址或任意文件读取URL。拒绝整个根目录/home等过宽范围；路径处理按实际运行系统核对。
4. docsPath及其祖先中的符号链接应明确识别；第一版保守拒绝通过符号链接注册，不能隐式跳过路径边界。
5. home与exclude只能是文档根内的相对路径。规范化和resolve后仍必须属于同一注册根，不能仅做字符串前缀比较。
6. 被匹配的文件也要拒绝符号链接、隐藏路径、凭据与工具输出，排除优先。
7. 每个首页与导航目标都必须实际存在且被允许；缺失时给出明确原因，不默默开放父目录寻找替代。
8. 对同一目录的重复/重叠注册给出提示并要求明确归属，不擅自覆盖现有项目项。

## 一个项目，多个文档目录

同一个项目的文档常常分散在仓库各处：`docs/` 放总索引，`mid-system/docs/`、`iot-system/docs/` 各放子系统文档，`devops/` 放运维手册。这些属于同一个项目，不应该被拆成四个互不相干的阅读入口。

因此一个项目可以登记多个目录，每个目录带一个 `prefix` 决定它在项目里的位置：

```json
"roots": [
  { "prefix": "",           "path": "/path/to/repo/docs" },
  { "prefix": "mid-system", "path": "/path/to/repo/mid-system/docs" },
  { "prefix": "iot-system", "path": "/path/to/repo/iot-system/docs" },
  { "prefix": "devops",     "path": "/path/to/repo/devops" }
]
```

收录后的项目内路径就是 `prefix` 加上目录内的相对路径。四个目录各自的 `README.md` 分别落在 `README.md`、`mid-system/README.md`、`iot-system/README.md`、`devops/README.md`，不会互相覆盖。

规则：

1. `prefix` 在项目内唯一，且不能互相嵌套（`a` 与 `a/b` 不能并存）；至多一个目录用空 `prefix`。
2. 登记的目录之间不能互相嵌套，否则同一个文件会被收录两次。跨项目的目录重叠同样拒绝。
3. `exclude`、`home` 和范围说明页都按项目内路径（含前缀）工作，例如 `devops/servers.md`；排除一整个目录写 `devops/`。
4. 极端情况下两个目录仍可能产生同名的项目内路径（例如空前缀目录里正好有个 `devops/` 子目录）。后遍历到的文件不会静默覆盖先到的，而是记为 `与其他文档目录同名` 出现在排除报告里。
5. 自动同步会监听全部已登记目录；watch 数量按目录总数计算。
6. 单目录项目继续用 `docsPath`，语义等价于一个空前缀的 `roots`，不需要改写。

在管理后台的项目卡片里，文档目录是一个可编辑的文本框，每行一条，写成 `项目内位置 = 主机上的绝对路径`；留空位置就是挂在项目根下。保存后立即重新构建。

## 收录范围与隐私规则

收录范围是黑名单：每个登记目录默认整体收录，只有命中 `exclude` 或强制安全规则的条目才被挡下。

这里不提供白名单。逐文件白名单会让源目录新增的文档永远不出现，而同步结果仍然显示成功——范围配错表现为一次成功的同步，是最难发现的一类故障。黑名单把默认值放在“会出现”这一侧：漏配一条排除规则会多发布一个文件并在报告里列出来，而漏配一条白名单会永久少发布一个文件且毫无提示。

下列规则对每个登记目录都强制生效，`exclude` 能收紧范围但无法放开它们：

| 层级 | 规则 | 处理 |
| --- | --- | --- |
| 路径 | 隐藏路径、`__pycache__`/`node_modules`/`target`/`logs`/`.git`、符号链接、越界路径 | 不导出 |
| 文件名 | `.env`/`*.env`、`.key`/`.pem`/`.p12`/`.pfx`/`.pub`/`.ppk`/`.jks`/`.keystore`/`.kdbx`，以及 `credentials*`/`secret(s).json`/`id_rsa`/`id_dsa`/`id_ecdsa`/`id_ed25519`/`known_hosts`/`authorized_keys`/`ssh_config`/`.netrc`/`.htpasswd` | 不导出 |
| 类型 | 不在支持扩展名内的文件（含无扩展名文件） | 不导出 |
| 内容 | 文本文件含 `-----BEGIN ... PRIVATE KEY-----` | 不导出，刷新结果记录原因 |
| 内容 | 疑似明文口令/令牌赋值（排除 `${VAR}`、`changeme`、`example` 等占位） | 仍然收录，但在刷新结果和首页同步反馈中提示，由负责人决定是否加入exclude |

内容级检查只读取文件开头不超过512KB，并且只输出路径和规则名称，不输出命中内容。低置信度命中选择“提示而不拦截”，避免把正常文档静默藏起来，重新制造同一类失败。

这些规则降低误收录的概率，但不等于访问控制：8000监听 `0.0.0.0` 且不设登录，凡是收录的内容，能访问该端口的设备都能读。真正敏感的文件应该先在exclude中排除，或者不要放进注册的docs目录。

## 链接与附件

文档相对链接应先相对源文档解析，再检查允许范围，最后按类型生成阅读/下载地址。链接中的fragment用于章节定位，不能混入主机文件路径。

允许的同项目Markdown在项目路由内阅读；HTML进入受限预览；CSV/XLSX等附件进入明确下载地址。外部HTTP链接保持外链，不预抓取其内容。

未允许目标显示说明和本地源路径线索，不能通过点击链接偷偷注册另一个目录。未来如果支持跨项目链接，应先验证目标项目已注册、目标文件被允许，再转换为明确的跨项目入口。

## 操作流程

### 页面快速接入

打开 `http://localhost:8000/` 或可达的 `http://<主机IP>:8000/`，输入运行服务的主机上的docs绝对路径（可用`~/`），点击“接入项目”。点击表示明确允许发布该根目录内所有支持类型，页面显示范围说明，不扫描文档内容作人工安全审查。远程访问时，路径仍属于服务主机，不是访问设备。

服务自动使用目录名作为名称，ID为URL安全的目录名加路径哈希短后缀，避免多个目录均名为docs时冲突。首页优先README.md，否则选择排序后第一个可发布Markdown。没有Markdown、路径不存在、经过符号链接、路径穿越、与已有项目重叠时拒绝。名称含中文仍可生成稳定URL。

新项默认收录整个注册根，`exclude` 初始为空，沿用全部强制规则；既有项目的排除规则不受影响。全部内容先在临时目录构建成功后才写入新配置并发布；失败回滚配置，不报告接入成功。改名、增删排除规则和取消接入在 `/admin.html` 管理后台完成，也可继续使用本机JSON/CLI。

### 新项目

确认文档根和允许范围 → 只读校验 → 展示将纳入/排除的文件清单 → 保存注册项 → 生成项目导出与导航 → HTTP和浏览器验证 → 报告真实访问地址与限制。

### 更新注册

读取现有项 → 保留无关配置 → 说明范围变化 → 重新验证 → 刷新导出及搜索缓存。扩大文件范围是权限变化，需要负责人明确确认。

### 取消注册

确认目标ID → 删除该注册项的导航/索引/导出副本 → 验证旧URL不能再读取 → 保留原项目源文件。若操作由agent提出而非用户要求，不得自行取消项目。

### 文档内容更新

由各项目维护原文，再点击首页“同步最新文档”或执行refresh（当前均刷新全部已注册项目）。刷新不安装依赖、不重启业务服务、不改变注册范围。没有自动文件监听或跨项目全局搜索。

刷新结果分四类，首页同步反馈和管理后台同样展示：已收录文件数、复用的未变更文件数、被规则或exclude排除的条目、疑似含明文口令的已收录文件。最后一类出现时按警告样式显示，不能只报“同步完成”。另外，没有额外排除任何条目的exclude规则记在项目结果的 `unusedExclude` 里，管理后台保存后以警告显示，并常驻在项目详情的排除规则下方，避免写错的规则看起来像排除成功。每个项目还会生成 `#/__scope.md` 范围说明页，把排除原因长期留在阅读界面里。

开启 `settings.autoSync` 后，注册根的文件变化会在防抖窗口结束后自动触发同一套重建流程。自动同步与手动同步共用一把操作锁：手动操作进行中时自动同步跳过这一轮，下一次文件变化会再次触发。
