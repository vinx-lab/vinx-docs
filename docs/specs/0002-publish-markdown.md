# 用短链接发布单个 Markdown 文件

## 问题

agent 写完的东西经常是一份 Markdown（方案、报告、会议纪要），用户想要一个链接直接看、直接批注。现在 `vinx-docs publish` 只接受 `.html` 入口：

```text
$ vinx-docs publish docs/plan.md
Error: 入口页必须是存在的.html文件
```

agent 实际遇到这个限制时的反馈（摘要）：

- skill 只写了 HTML 怎么发，没写 Markdown 能不能发、不能发时怎么办；`publish --help` 也只写「入口 .html 文件」。
- 于是 agent 自己换了一条路：把所在目录用 `register` 登记成文档项目，再给阅读页链接。这条路没有短链接，还改了用户的项目登记，登记范围也是整个目录，而不是一个文件。
- 它本应先直接试 `publish`（校验失败不会改动任何东西），失败后停下来问用户，而不是自己换机制。

现在的绕法都不理想：

| 绕法 | 问题 |
| --- | --- |
| 登记成文档项目 | 没有短链接；登记的是整个目录，改动用户配置；一次性的文件不该变成长期项目 |
| agent 把 Markdown 转成 HTML 再发布 | 要有转换工具；渲染和阅读页不一致（Mermaid、表格、相对链接）；批注和编辑落在生成的 HTML 上，不是源文件，批注交给 agent 后改错文件 |

## 现状（实现事实）

- 短链接 `/a/<短码>/` 由 `internal/pages` 登记入口和文件清单，服务端每次请求重新校验，只放行清单里的文件；响应带页面专用的沙箱 CSP（origin 为 null，允许脚本，不能调用管理接口）。清单从入口 HTML 出发，沿 HTML/CSS/JS 的相对引用收集。
- 页面列表里的预览（`published.html`）把页面放在沙箱 iframe 里，批注和编辑在外层完成，批注目标是 `a:<短码>/<文件>`。
- 文档阅读页用 Docsify 在站点源里渲染 Markdown（严格 CSP，禁止内联脚本），支持 Mermaid、表格、页内编辑和批注，批注目标是 `doc:<项目>/<文件>`。
- 程序没有服务端 Markdown 渲染器，Markdown 都在浏览器里渲染。

## 方案候选

### A. 只改 skill：agent 先转 HTML 再发布

不改程序。缺点见上表，批注回不到源文件，这一条与「批注直接交给 agent 修改」的定位冲突，只适合作为临时办法。

### B. 沙箱页内渲染

`publish` 接受 `.md`，`/a/<短码>/` 返回一个服务端生成的外壳 HTML，在沙箱里加载 Docsify 渲染该文件。

- 好处：链接形态和 HTML 页面完全一样。
- 问题：沙箱页调不了管理接口，批注和编辑仍要走外层预览；外壳要另写一套渲染配置，和阅读页重复。

### C. 短链接打开站点内的单文件阅读页（已选定）

`publish` 接受 `.md`，登记项标记为 Markdown 类型。访问 `/a/<短码>/` 时重定向到站点里的单文件阅读页（例如 `/read.html?a=<短码>`），由它取 `/a/<短码>/<文件>.md` 渲染。

- 渲染复用文档阅读页的 Docsify 配置（Mermaid、表格、代码高亮、深浅色、手机布局），和登记项目里的文档看起来一样。
- 批注目标沿用 `a:<短码>/<文件>`，页内编辑写回源 Markdown，和现有 HTML 页面的批注、交给 agent 流程一致。
- 在站点源里渲染，受站点严格 CSP 约束（不执行内联脚本），安全性与现有文档阅读页相同。
- 文件清单：入口 `.md` 加上它相对引用的图片等资源（`![](img/a.png)`、行内 `<img src>`）；链接到的其他 `.md` 默认不收，需要时用 `--file` 显式加入。

## 取舍

- 选 C 不选 B：批注和编辑是核心功能，B 要么放弃、要么再造一套；C 复用已有的阅读、批注、编辑实现。
- 不引入服务端 Markdown 库：会新增依赖，且渲染结果与阅读页不一致。
- 不自动跟随 `.md` 之间的链接：发布范围保持「一个文件加它的资源」，要多个文件时用 `--file` 或登记项目，避免相对链接扩大授权范围。

## 细节决定

维护者选定方案 C。以下是实现时的默认做法，实现中发现问题再回到这里修改：

1. 地址：`/a/<短码>/` 重定向到站点的单文件阅读页（如 `/read.html?a=<短码>`）。阅读页走站点 CSP，不在沙箱里返回阅读页外壳，避免为它另定安全头。给用户的链接仍然是 `/a/<短码>/`。
2. 清单外链接：沿用文档阅读页的「范围说明」样式，不自动扩大清单。
3. 页面列表：Markdown 条目标注「Markdown」，预览区直接嵌入阅读页（可批注、编辑）。
4. 实时刷新：沿用短链接现有的版本号轮询，源文件修改后自动重新渲染。
5. 同时更新 `publish --help`（入口可以是 `.html` 或 `.md`）和 `skills/vinx-docs/SKILL.md`。

## 近期先做（不改程序，已完成）

已更新 `skills/vinx-docs/SKILL.md`（`publish --help` 留到实现 C 时一起改）：

- 写明目前 `publish` 只接受 `.html`，Markdown 不能直接发短链接。
- Markdown 要给用户看时先问用户：转成 HTML 发布（批注不回源文件），或给文档阅读页链接（需要已登记的项目，登记要用户同意）。
- 遇到 skill 没覆盖的情况：先直接试命令（校验失败不会改动任何东西），失败就停下来问用户，不要自己换机制或改配置。
- 顺带补清的边界：`register`、`unregister`、`settings`、`unpublish`、`stop`/`restart` 只在用户明确要求时执行；临时目录里的页面重启后失效；一次发布多个页面用一个监听写多个范围；批注只改它指向的源文件，涉及其他项目先问；一条批注有多件事时全部做完才标记解决。

## 验证

- 单元测试：`.md` 入口校验、清单收集（图片、`<img>`、忽略外部链接和上层目录）、登记与重复发布沿用短码。
- HTTP：`/a/<短码>/` 的重定向或外壳、`.md` 源文件的类型与安全头、清单外文件 404。
- 真实浏览器：渲染（Mermaid、表格、深浅色、手机宽度）、批注创建与交给 agent、页内编辑保存回源文件、源文件修改后自动刷新、没有外部请求。

## 结果

- 按方案 C 实现。`/read.html?a=<短码>` 复用文档阅读页（`reader.js` 单文件模式，不显示侧栏），清单由 `/a/<短码>/__docsify_x/manifest` 提供，批注目标是 `a:<短码>/<文件>`。
- 页面列表预览 Markdown 时直接嵌入阅读页，所以 `/read.html` 的 `frame-ancestors` 放宽为 `'self'`，其他站点页面不变。
- 扫描图片时跳过代码块和行内代码。阅读页把 front matter 显示为代码块（文档项目同样受益）。
- 验证：Go 单元与 HTTP 测试；浏览器测试 `tests/browser/markdown.cjs`（跳转、图片、Mermaid、清单外链接、批注、编辑写回、外部修改提示、页面列表预览、无外部请求）；桌面和手机宽度截图。
- 未验证：Windows、macOS 上的浏览器表现。
