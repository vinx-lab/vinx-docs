# 短链接下载源文件、本页目录跳转与左侧目录

## 问题

- 短链接页面上拿不到源文件：Markdown、图片、音视频在阅读页里渲染，HTML 页面注入了自动刷新脚本，想留存或转交只能去源目录找。
- 「本页目录」的链接写成 `#<标题id>`，Docsify 把它当成路由，点了显示 404（短链接阅读页和项目阅读页都有这个问题）。
- 单文件阅读页（短链接）没有侧栏，本页目录浮在正文右上角，读到后面就找不到了。

## 方案

- 新增保留路由 `/a/<短码>/__docsify_x/download`，和 `version`、`manifest` 同属 `__docsify_x`，访问控制与短链接相同：
  - 清单只有一个文件时原样发送，支持 `Range`、`HEAD`；清单有多个文件时，把仍通过发布检查的文件按原目录结构打成 zip，包内顶层目录与 zip 同名。HTML 都不注入脚本。
  - 文件名可选：默认按页面标题（单个文件保留原扩展名，如 `订单看板方案.md`；多个文件是 `订单看板方案.zip`），`?name=file` 按原文件名（`plan.md`、`index.zip`）。标题去掉不能做文件名的字符，截到 80 字，为空时退回原文件名。`Content-Disposition` 里非 ASCII 文件名按 RFC 2231 编码。
  - 每个文件照常过 `CheckFile`，不会带出清单外、隐藏或凭据文件。
- 入口都是「下载源文件」下拉菜单，两项「按标题命名」「按原文件名」，各自显示将得到的文件名，两个名字相同时只留一项：阅读页顶栏（Markdown、图片、音视频）、页面列表顶栏（HTML）、单独打开的 HTML 页面右下角。阅读页清单和 `/api/artifacts` 摘要增加 `downloadUrl` 和 `downloadNames {title, file}`。
- 目录链接改用 Docsify 给标题生成的锚点（`#/<路由>?id=<标题>`）。点击时自己滚动（标题带 `scroll-margin-top` 让开固定顶栏），只用 `history.replaceState` 更新地址，不触发 Docsify 的滚动（它会把标题顶到顶栏下面）。
- 单文件阅读页：本页目录固定在左侧、垂直居中，正文右移让出位置；随滚动高亮当前小节；右上角 × 收起，收起后左边缘留一个「目录」按钮。
- 左侧目录收二到四级标题（h2–h4），按层级成树：有子项的条目前面有折叠按钮，顶部有「全部展开」「全部折叠」。标题不超过 12 个时默认全部展开，否则默认折叠、只展开当前小节所在的分支；滚动时自动展开当前分支（当前小节自己和它的各级上级），离开后再收起，手动展开或折叠过的分支不再自动变化。点有子项的目录项时跳过去并展开它（算手动展开）；平滑滚动途中不跟随，避免沿途的分支开了又关。当前小节在折叠的分支里时，分支标题高亮。宽屏记住收起状态（`localStorage`），窄屏（≤900px）默认收起，展开时浮在正文上，点目录项后自动收起。项目阅读页的目录位置不变（左侧已有 Docsify 侧栏）。

## 取舍

- 多文件只下载入口文件：HTML 引用的样式、脚本、图片会缺失，下载后打不开，所以打成 zip。
- 先读进内存再发 zip：大视频会占内存；改为边读边写，代价是中途出错只能断开连接（浏览器显示下载失败）。
- 滚动时只展开、从不收起：滚过一遍长文档后所有分支都开着，折叠就没有意义了。
- 目录用 Docsify 侧栏的 `subMaxLevel` 显示：短链接阅读页本来就隐藏了侧栏，打开侧栏会带出不需要的项目导航，不如单独做目录。

## 验证

- Go：`TestArtifactDownload`（单文件原样、按标题和按原文件名两种命名、非 ASCII 文件名、多文件 zip 内容与目录结构、HTML 不注入脚本、清单里的 `downloadNames`、源文件删除后 404、未知短码 404）。
- 真实浏览器（`tests/browser`）：Markdown 短链接目录在左侧、点击后标题在顶栏下方且不是 404、当前项高亮、三四级标题折叠展开、收起再展开；阅读页下载菜单两种命名都能下载，zip 包含 Markdown 和图片；单独打开的 HTML 页面下载成功。

## 结果

已实现。Go 测试、`tests/links.test.cjs` 和 `tests/browser` 四项全部通过。本机内核限制非特权 user namespace，Chromium 沙箱起不来，浏览器测试是在临时副本里关掉 `chromiumSandbox` 跑的；仓库里的测试脚本没有改沙箱设置。手动检查过手机宽度（390px）：目录默认收起、展开后浮在正文上、点目录项后收起、没有横向滚动；用 4 章 × 2 节 × 2 条的文档检查过树形目录的自动展开和收起。
