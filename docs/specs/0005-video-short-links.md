# 短链接支持视频

## 问题

agent 做的演示录屏、截屏动画（MP4、WebM）要给用户看，短链接现在用不了：

- 文件整份读进内存后一次发出，不支持 `Range`：Safari / iOS 不播放，Chrome 不能拖动进度，大文件每次请求都占一份内存。
- 入口只能是 `.html` / `.md`，不能直接发布一个视频。
- Markdown 阅读页里 `![](demo.mp4)` 显示为「未收录图片」；链接到视频只给下载。
- 发布时会把清单里每个文件（包括视频）整份读成文本去找引用。

## 方案

- 短链接里非 HTML 文件改为流式发送，支持 `Range`（206）和 `HEAD`；安全头（CSP、`nosniff` 等）不变。HTML 仍整份读入以注入自动刷新脚本。
- 入口可以是图片或音视频（`.png` `.jpg` `.jpeg` `.gif` `.webp` `.svg` `.mp4` `.webm` `.mp3` `.wav`）：和 Markdown 一样跳到单文件阅读页，有同样的顶栏（返回文档中心、搜索、字号、深浅色、批注）。正文由服务生成（`__docsify_x/view.md`：标题 + 这一个媒体），不是源文件；批注挂在媒体文件上，编辑按钮隐藏。标题默认取文件名。媒体按屏幕高度等比缩小，一屏内看完；图片点击放大（先适应屏幕，再点看原始尺寸），视频用播放器自带的全屏，页面列表的预览框允许全屏。
- 单文件阅读页：清单里视频为 `kind: video`、音频为 `kind: audio`；Markdown 图片语法引用视频时渲染为 `<video controls>`，音频为 `<audio controls>`。Markdown 里写的 `<video src poster>` 也自动收进清单；阅读页把 Markdown 里原始 `<img>` `<video>` `<audio>` `<source>` 的相对地址按清单改写（原来原始 `<img>` 按阅读页地址解析，加载不到）。
- 只对 HTML、CSS、JS、Markdown 找引用和读标题，其他文件不再读内容。
- 页面列表里媒体发布标「图片」/「视频」/「音频」，预览框显示阅读页。

不改文档项目的收录与服务方式。

## 取舍

- 不做转码、缩略图或自建播放器：浏览器原生播放器够用，也不增加依赖。
- 媒体入口不直接返回文件：那样没有顶栏、不能返回主页和批注，与 Markdown 的体验不一致。
- 不加文件大小上限：只放行清单里的文件，流式发送不再占内存。

## 验证

- Go 测试：`Range: bytes=0-3` 返回 206、`Content-Range`、`video/mp4` 和页面 CSP；`HEAD` 返回长度、无正文；视频作入口可发布并直接返回文件；Markdown 引用视频时清单为 `video`。
- 前端单元测试：`resolveLink` 对 `video` / `audio` 条目返回对应类型。
- 临时实例 + 无头 Chromium：阅读页里视频能加载元数据（`readyState ≥ 1`），视频入口短链接能播放。

## 结果

按方案实现。Go 测试与 `tests/links.test.cjs` 通过；临时实例上 HTTP 检查 `Range` 返回 206 且带页面 CSP；无头 Chromium 中阅读页内嵌 MP4（moov 在文件尾）加载元数据并拖动到 2 秒成功，Markdown 里原始 `<video src>` 改写后可加载；视频、图片入口短链接跳到阅读页，顶栏完整、编辑按钮隐藏、批注面板可用，桌面和手机宽度（390px）都正常，1920×1080 视频和 1200×2600 长图都在一屏内完整显示，图片放大与原始尺寸切换、Esc 关闭正常，视频在短链接页和页面列表预览框里都能进入全屏；页面列表标「图片」「视频」，预览框加载阅读页。

未验证：Safari / iOS 真机播放。
