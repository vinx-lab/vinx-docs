# 外链分享：把单个文档或页面分享给不在同一网络里的人

## 问题

Vinx Docs 的链接只在能访问本机 8000 端口的设备上打得开（本机、局域网、同一 tailnet）。想把某一份文档或某个页面给同事、客户看时，现在只能：把文件发过去（Markdown 没渲染、HTML 页面缺资源），或者手动复制到飞书等平台（格式要重排，改了又要再贴一遍）。

issue 的要求：能分享到飞书这类平台，也考虑其他方式或自建服务器。

## 约束

- 8000 没有账号，写操作没有权限控制（README「安全模型」）。**不能让外部访问者碰到本机服务**，否则阅读、同步、登记、批注接口全部暴露。
- 数据出本机要由用户决定，而且各项目的边界不同：有的项目可以发飞书，有的只能发客户指定的地方，有的完全不能外发。
- 凭据（飞书应用密钥、服务器令牌）只能放在家目录的配置里，不进仓库、日志和页面。

## 方案

核心是**分享快照**：分享的内容是生成的只读副本，外部访问者拿到的是这份副本，永远不会回连本机。发出去的内容由用户在页面上确认。

### 1. 快照（所有出口共用）

- 分享对象：一篇已收录的文档（`doc:<项目>/<路径>`）或一个短链接页面（`a:<短码>`）。不支持整个项目。
- 生成：一个离线可用的目录，包括 `index.html`、清单里的资源，以及内嵌的本地 Docsify/Mermaid 资源。Markdown 用和阅读页相同的渲染配置；HTML 页面按短链接清单复制。不带批注、编辑、版本轮询脚本，也不带任何 `/api` 调用。
- 检查：复用收录与 `publish` 的路径、隐藏文件、凭据文件和私钥内容检查。相对链接指向快照以外的文件时，生成结果里列出来，链接改成「未包含」提示。
- 确认：阅读页和页面列表加「分享」按钮。先显示要发出去的文件清单、总大小、出口和有效期，确认后才生成和发送。命令行 `vinx-docs share <目标> --to <出口>` 走同样的确认（`--yes` 跳过确认，只在用户要求时使用）。
- 记录：分享记录写在家目录的 `config/shares.json`，包括目标、出口、外部地址、生成时间和源文件版本摘要。源文件改过以后，列表里显示「已过期，可重新分享」。**不自动重新推送。**

### 2. 出口（按阶段实现）

| 阶段 | 出口 | 做法 | 适合 |
| --- | --- | --- | --- |
| P1 | 下载 | 快照打成 zip，浏览器下载 | 发文件给对方，或上传到任何地方 |
| P2 | Cloudflare | 用户自己的 Cloudflare 账号和域名：Worker 提供访问和上传，快照存 R2，本机带令牌推上去，得到 `https://<分享域名>/s/<随机码>/` | 需要一个长期可用的链接，能控制有效期和撤回，不用运维服务器 |
| P3 | 飞书 | 调飞书开放平台，把 Markdown 导入成飞书云文档，并按设置开启「获得链接的人可阅读」 | 对方在飞书里工作；只支持 Markdown 文档 |

**P2 Cloudflare**（面向大陆以外的访问者；大陆访问慢且不稳定，不作为目标）：

- 组成：一个 Worker、一个私有 R2 桶（不开 `r2.dev` 公开访问，只经 Worker 读取）、一个 KV 命名空间（记录每个分享的有效期和状态）。Worker 绑定用户托管在 Cloudflare 的自有域名下的子域名，证书由 Cloudflare 签发。
- Worker 接口：
  - `GET /s/<随机码>/<路径>`：查 KV，有效就从 R2 读取文件，加上与短链接相同的沙箱 CSP、`X-Robots-Tag: noindex`；到期或撤回返回 410，不存在返回 404。
  - `PUT /api/shares/<随机码>`：带 `Authorization: Bearer <令牌>`，请求体是快照 zip，有效期放在请求头里；Worker 解包后写入 R2 和 KV。
  - `DELETE /api/shares/<随机码>`：撤回，删除 KV 记录和 R2 对象。
- 随机码 128 位，由本机生成。上传令牌存为 Worker secret，本机存在凭据文件里。另设 R2 生命周期规则，兜底删除超期对象。
- Worker 代码放在仓库的 `cloudflare/share-worker/`，不含账号 ID 和密钥，部署用 `wrangler`。部署步骤写进 `docs/`：建桶、建 KV、设 secret、绑定域名。
- 可选：访问者身份验证交给 Cloudflare Access（邮箱验证码，只放行指定邮箱），在 Cloudflare 面板里配置，不用写代码。
- 本机只用标准库发 HTTP，不引入新的 Go 依赖。出口配置记录分享域名和令牌。

**P3 飞书**：用自建应用的 `app_id` / `app_secret` 取 tenant_access_token，上传 Markdown，创建导入任务转成云文档，再设置链接分享范围（组织内或互联网）。具体接口、Markdown 导入对图片和表格的支持程度，实现前先用测试应用实测，写回本节。已知限制：Mermaid 保留为代码块；图片能否随导入带上待实测，带不上就改为单独上传后插入；飞书里的修改不会回写源文件。

### 3. 按项目限定出口

项目配置增加 `share` 字段，值是允许的出口列表，默认 `[]`（不能分享）。管理后台的项目设置里加勾选框。短链接页面没有所属项目，使用全局设置里的 `share.pages`，默认也是 `[]`。出口不在允许列表里时，分享按钮不显示，命令行报错并说明去哪里开启。

### 4. 凭据

出口配置（Cloudflare 分享域名和上传令牌、飞书应用密钥）存放在家目录的 `config/share-targets.json`，权限 0600。管理后台只显示「已配置 / 未配置」和替换按钮，不回显内容，日志里不打印。

## 取舍

- **不做本机服务直接对外**（Tailscale Funnel、Cloudflare Tunnel、端口映射）：链接实时、实现最少，但外部访问者会直接碰到没有鉴权的 8000，而且需要改网络配置。只开一个只读端口再加隧道可以缓解，但机器关机时链接就打不开，也会增加长期暴露面。
- **快照而不是实时同步**：外部副本和本机完全断开，安全边界清楚；代价是更新要手动重新分享。
- **Cloudflare Workers + R2，而不是自租服务器跑 `share-serve`**：不用维护主机、TLS 和系统更新，个人用量在免费额度内，R2 不收出流量费。代价是绑定 Cloudflare，而且大陆访问差。上传协议只是 HTTP PUT/DELETE 加令牌，以后要换成自建服务器，照同一个协议实现服务端即可。
- **不用 Cloudflare Pages 或 R2 公开桶直接托管**：做不到按链接设置有效期和撤回，也不方便统一加 CSP 响应头。
- **飞书放最后**：需要应用凭据和企业权限，接口细节要实测，只覆盖 Markdown。P1 的 zip 已经能手动上传到飞书云盘。
- **不做整个项目的分享**：范围大，容易误发；需要时逐篇分享。

## 验证

- P1：Go 测试覆盖快照清单（含拒绝隐藏文件、凭据文件、清单外链接）、zip 内容，以及快照 HTML 不含 `/api`、不含批注脚本。在真实浏览器里断网打开解压后的 `index.html`，Mermaid 和表格正常。
- 按项目限定：`share: []` 的项目没有分享按钮，接口返回 403。
- P2：本地用 `wrangler dev`（模拟 R2 和 KV）测试上传、访问、过期 410、撤回 410、令牌错误 401、随机码不存在 404，并确认响应头有沙箱 CSP。Go 端的推送用测试服务器验证。部署到真实账号并从外网访问，需要用户的账号和域名，列为未验证项，直到实测完成。
- P3：用测试应用导入一篇含表格、代码、图片的文档，人工检查飞书里的效果和链接权限。这一步需要用户提供测试应用，属于未验证项，直到实测完成。
- 所有测试使用临时的 `VINX_DOCS_HOME`，不动真实项目和运行数据。
