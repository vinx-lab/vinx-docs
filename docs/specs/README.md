# 需求说明

较大的改动在动手前先在这里写一份说明，完成后在同一文件里补上结果。这里的文件是正本；对应的 issue 只放摘要和链接，讨论得出的结论要写回文件。

## 命名

`NNNN-简短标题.md`，编号四位、递增，例如 `0001-page-comments.md`。

## 模板

```markdown
---
issue: 12          # 没有对应 issue 时删掉这一行
status: draft      # draft（写方案中）→ ready（等实现）→ done（已实现），或 dropped（不做）
---

# 标题

## 问题
要解决什么，谁会遇到，现在怎么绕过去。

## 方案
打算怎么做，影响哪些模块、接口和数据。

## 取舍
考虑过但没选的做法，以及原因。

## 验证
怎么证明做对了：测试、HTTP 检查、真实浏览器检查。

## 结果
完成后补：实际改了什么、验证结果、未验证项、后续事项。
```

## 注意

这些文件会公开，不要写本机路径、主机名、内网地址、个人或客户信息。
