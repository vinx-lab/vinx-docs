# 经反向代理对外访问时的密码登录

## 问题

要用 HTTPS 反向代理把服务开到外网（用域名访问）。现在没有账号，任何能连上的人都能阅读全部项目、保存源文件、写批注、登记目录、改设置。另外写接口只认 `Origin: http://<Host>`，套上 HTTPS 反代后页面上的写操作会全部 403。

目标：

- 外部访问要登录（单个密码）；内网直连保持现状，不用登录。
- 短链接发布后 24 小时内，外部访问者不登录也能只读查看；过期后要登录，重新发布重新计时。
- 项目可以单独设为「公开阅读」，外部不登录也能读，默认不公开。写操作一律要登录。

## 方案

### 1. 识别外部请求（单端口）

不另开端口，沿用现有端口。满足任一条件就按外部处理：

- 请求带 `X-Forwarded-For`、`X-Forwarded-Host`、`X-Forwarded-Proto`、`Forwarded`、`X-Real-IP` 之一。本机直连不会带这些头，伪造只会让请求受更多限制。
- `Host` 是管理后台登记的外部域名（小写、去掉端口后比较）。

不按来源 IP 判断：反代经内网或 tailnet 连进来，来源地址就在内网段里。

### 2. 访问规则（外部请求）

| 内容 | 未登录 | 已登录 |
| --- | --- | --- |
| `/`、`/read.html`、`/login.html`、`/assets/*`、`/vendor/*`、`/healthz` | 可以 | 可以 |
| `/catalog.json`、`/search-index.json` | 只返回公开项目的条目 | 全部 |
| `/projects/<公开项目>/…` | 只读 | 完整 |
| `/projects/<其他项目>/…`、管理后台、批注页、页面列表 | 页面跳转登录，其余 401 | 完整 |
| `/a/<短码>/…`，发布后 `linkHours` 小时内 | 只读 | 完整 |
| 同上，已过期 | 页面跳转登录，其余 401 | 完整 |
| `/api/*`（`/api/auth`、`/api/login`、`/api/logout` 除外） | 401 | 完整 |

- 有效期按发布记录已有的 `publishedAt` 计算（重新发布会更新它），不新增字段；`linkHours` 改了立即对所有短链接生效。`linkHours = 0` 表示短链接一律要登录。
- 外部未登录访问不存在的短码计入失败限流，防止枚举 6 位短码。
- 外部访问的 HTML 外壳在 `<html>` 上标 `data-vinx-auth="guest|user"`（不发 ETag）。前端据此隐藏编辑、批注和管理入口（`.needs-login`），未登录时阅读页不挂批注、不调接口；顶栏加「登录」或「退出」。内网页面不加标记。
- 写操作的 `Origin` 检查：外部请求按 `<X-Forwarded-Proto>://<X-Forwarded-Host 或 Host>` 比对，内网仍是 `http://<Host>`。
- 前端原来对接口请求用了 `credentials: 'omit'`，外部登录后会带不上 Cookie，全部去掉（同源默认带）。

### 3. 密码与会话

- 新包 `internal/auth`。`config/auth.json`（0600）存 PBKDF2-SHA256 摘要（60 万次、16 字节盐，Go 标准库 `crypto/pbkdf2`，不引入新依赖）、外部域名和 `linkHours`；`config/sessions.json`（0600）只存令牌的 SHA-256。
- 登录 `POST /api/login {password}`，成功发 128 位随机令牌 Cookie `vinx_session`：`HttpOnly`、`Path=/`、30 天；HTTPS 时 `Secure; SameSite=None`（短链接页面在 CSP 沙箱里，origin 为 null，加载资源算跨站，Lax 带不上 Cookie），HTTP 时 `SameSite=Lax`。会话重启后仍有效，改密码时全部注销。
- 同一来源连续 5 次失败锁 15 分钟；全部来源一分钟内失败超过 30 次时暂停一分钟。来源取 `X-Forwarded-For` 最后一项。
- 管理接口：`POST /api/auth/password`、`/api/auth/settings`（`externalHosts`、`linkHours`）、`/api/auth/logout-all`，只允许内网调用。`/api/config` 多返回 `auth`（是否设了密码、域名、时长、有效会话数），不含摘要和令牌。
- 只在管理后台设置密码（设置集中在后台），不加命令行入口。

### 4. 公开项目

项目配置增加布尔字段 `public`（默认不写，即不公开），后台项目详情加「公开阅读」勾选框，`/api/project/update` 接受 `public`。只影响外部未登录访问，不影响收录范围。

### 5. 页面

- 新增 `login.html`、`assets/login.js`（登录后只跳转站内路径）、`assets/auth.js`（各页面加载）。
- 管理后台新增「外部访问」：设置密码、注销所有登录、外部域名、短链接免登录时长。
- 页面列表在免登录期内显示「外部免登录还剩 N 小时」（`/api/artifacts` 多返回 `publicUntil`）。

反代本身的配置不在本仓库实施；要求写在 `docs/deployment.md`。

## 取舍

- **另开一个只给反代用的端口**：从结构上不会把外部请求认成内网，但要多开端口、反代指向新端口。按维护者的选择只用一个端口；代价是识别依赖反代至少转发一个头或保留 `Host`，所以同时支持登记域名作为第二道识别，部署说明写明要求。
- **按来源 IP 区分内外**：反代经 tailnet 进来时来源就是内网地址，等于外部全部免登录，不采用。
- **反代做 Basic Auth**：做不到短链接和公开项目免登录，也不能退出，不采用（可以另外叠加）。
- **多账号、权限分级**：单人自用，不做。
- **与 spec 0004 的关系**：0004 因为服务没有鉴权而不让本机服务直接对外，选了快照。本方案给外部访问加上登录后，实时访问成为另一条路；给不该连回本机的人仍用 0004 的快照。

## 验证

- Go 测试（临时 `VINX_DOCS_HOME`）：内网请求行为不变；外部未登录时私有项目、管理页、`/api/*` 读写、写批注都被拒绝，`%2F..%2F` 和 `//` 绕不过项目检查；项目清单（含 `recent`）和搜索索引只剩公开项目；短链接有效期内可读、过期 401 / 跳转登录、`linkHours=0` 一律要登录；猜错 5 个短码后限流且不影响其他来源；没设密码不能登录；登录 Cookie 属性；登录后能访问全部、写操作 `Origin` 按 `https://<域名>` 比对；外部不能改密码；退出和改密码后会话失效；锁定期间正确密码也被拒；只靠登记域名、只靠转发头都能识别为外部；会话重启后仍有效、过期失效、两个文件 0600 且不含密码和令牌原文。
- 现有 Go 测试、`tests/links.test.cjs` 和 `tests/browser/run.cjs` 四项浏览器测试全部通过（内网行为不变）。
- 临时实例 + 无头 Chromium（带转发头模拟反代，桌面和 390px 宽度）。

## 结果

按方案实现，验证全部通过。浏览器实测：未登录首页只列公开项目，顶栏只有「登录」和「深浅色」；公开项目和 24 小时内的 Markdown 短链接能读，编辑、批注按钮隐藏；私有项目和过期短链接跳转登录，错误密码提示「密码不正确」；登录后回到原页面，后台、私有项目、编辑可用，「退出」后回到登录页；页面无脚本错误，手机宽度无横向滚动。管理后台「外部访问」和「公开阅读」勾选框在两种宽度下显示正常。

未验证：真实 HTTPS 反代下的访问（`Secure` / `SameSite=None` Cookie、`Origin` 按 `https://` 比对只在 Go 测试里验证过），等反代配好后在外网按 `docs/deployment.md` 末尾的方法检查。
